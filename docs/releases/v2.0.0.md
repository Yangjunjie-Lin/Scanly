# Scanly SDK v2.0.0 Stable

Scanly SDK v2.0.0 is the Stable software distribution. It is local-first:
image pixels and barcode payloads stay on the device unless an application
explicitly exports them. The release source, artifact, SBOM, license, API/ABI,
and manifest identities are recorded under `release/stable/`.

## Supported surfaces

- Web SDK: browser upload/camera runtime with Chromium, Firefox, and WebKit automated coverage.
- Node SDK: local image decoding and capture-router composition.
- React: `useScanly` adapter over the browser runtime.
- Native iOS: `ScanlySDK` Swift Package Manager source package, iOS 13+.
- Native Android: `io.scanly.sdk` AAR boundary for `arm64-v8a` and `x86_64`; `armeabi-v7a` is unsupported.
- Realtime scanning, tracking, batch identity, and industrial recovery are included in the frozen v2 API surface.

## Privacy and offline behavior

Decode, parsing, tracking, and industrial recovery are local-only. After the
package and WASM asset have loaded, network isolation does not disable decode;
applications remain responsible for their own telemetry and storage choices.

## Known limitations

- Physical device validation is continuing post-release under Issue #13.
- Do not interpret automated browser, simulator, or emulator coverage as complete physical-device qualification.
- Web iPhone/Android, Native iOS/Android, 30-minute camera soak, 60-minute extended soak, and the full device matrix are `POST_RELEASE_VALIDATION_PENDING`.
- DPM remains experimental and is not an industrial certification or accuracy guarantee.
- `armeabi-v7a` is not shipped. CocoaPods, Maven Central, App Store, and Google Play publication are not required v2.0.0 channels unless separately configured.
- Difficult/occluded symbols, strong perspective, camera permissions, thermal limits, and browser hardware capabilities can affect results.

Physical device validation is continuing post-release. No statement in these
notes means fully validated on all devices, device-certified, or
industrial-certified.
