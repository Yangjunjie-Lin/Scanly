# Scanly SDK v2.0.1

Scanly SDK v2.0.1 is a correctness and release-engineering patch for the v2 Stable line. It does not add barcode formats, decoders, tracking or batch features, UI, or public lifecycle states.

## Runtime fixes

- `ScannerSession.dispose()` is now terminal. A disposed session cannot be restarted, reset, or revived by switching sources.
- `ScannerSession.stop()` remains restartable, preserving the documented `start → stop → start` lifecycle.
- Disposal becomes terminal synchronously, shares one cleanup promise across repeated calls, cancels active decoding, drains scheduler work, and blocks late source or decode completions from restoring `scanning`.
- Owned decoders are disposed exactly once. Injected decoders remain caller-owned, while the `ScannerSession` that referenced them still becomes terminal.
- Owned frames are released exactly once, borrowed frames remain caller-owned, and late state/result/observation/diagnostic/listener publication is suppressed.
- Capture pre-abort handling, React concurrent replacement/rejection, reset/cancel stale completion, React StrictMode replay, and browser camera exception mapping include the fixes merged after v2.0.0.

## Compatibility

- All ten public npm packages remain on the v2 API surface.
- `ScannerSessionState` is unchanged; terminal identity is private and reports misuse through the existing `session_disposed` error code.
- No supported barcode format, platform minimum, Node.js range, Native ABI shape, or distribution channel is expanded.
- Exported version constants and package metadata report `2.0.1`; no other public declaration change is intended.

## Distribution

- npm: ten `@scanly/*` packages published to `latest` through GitHub Actions OIDC Trusted Publishing with provenance.
- iOS: `native/ios` at the signed `v2.0.1` tag, consumed as a local Swift package after exact-tag checkout.
- Android: `scanly-sdk-2.0.1.aar` attached to the GitHub Release for `arm64-v8a` and `x86_64`.
- Maven Central and CocoaPods are not v2.0.1 distribution channels.

The v2.0.1 qualification manifest, checksums, SBOM, licenses, reproducibility report, and artifact identities live under `release/stable/v2.0.1/`. The v2.0.0 files under `release/stable/` remain frozen.

## Validation boundary

Automated unit, coverage, browser, benchmark, package, API/ABI, simulator, emulator, and artifact checks do not constitute physical-device qualification. Issue #13 continues to track the v2.0.0 post-release physical program. Web iOS/Android, Native iOS/Android, 30-minute and 60-minute physical camera soaks, and the complete physical matrix remain `POST_RELEASE_VALIDATION_PENDING`; all admitted physical counts remain zero. This release makes no all-device, hardware, or industrial certification claim.
