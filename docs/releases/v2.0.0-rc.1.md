# Scanly SDK v2.0.0-rc.1

This is an immutable software candidate for final physical validation. It is
not a stable release and is not published to npm `latest`, Maven Central,
CocoaPods, the App Store, or Google Play.

## Included

- Multi-symbology decode, realtime scanner runtime, tracking, batch, and bounded
  industrial recovery from the merged Beta 1-Beta 5 source.
- Native C core, Swift Package (`iOS 13`, Swift tools 5.9), and Android AAR
  (`minSdk 24`, `arm64-v8a`/`x86_64`).
- Frozen JavaScript/TypeScript declarations, C ABI, Swift API, and Kotlin API.
- CycloneDX SBOM, third-party license inventory, checksums, provenance, and
  reproducibility comparison as CI artifacts.

## Supported formats

`qr_code`, `data_matrix`, `pdf417`, `code_128`, `ean_13`, `ean_8`, `upc_a`, and
`upc_e`. DPM recovery is experimental and opt-in.

## Known limitations

- Physical Web iOS Safari, Web Android Chrome, Native iOS, Native Android,
  desktop webcam, and 30/60-minute physical camera soaks are deferred to the
  final RC validation campaign (Issue #13 remains open).
- `armeabi-v7a` is unsupported.
- Curved recovery is bounded and not a certification claim.
- The historical `14-damaged` smoke limitation remains documented where the
  fixture is used.
- Production signing keys are not established: `SIGNING_NOT_YET_PRODUCTION`.

## Migration from v1

Use [the v1-to-v2 migration guide](../migration/v1-to-v2.md). Public APIs are
release-candidate stable; breaking changes require a new RC and an API/ABI
review.

## Gate boundary

Automated scanner, tracking, industrial, browser, native, security, SBOM,
license, and artifact gates must pass. Physical validation is explicitly
`DEFERRED_TO_FINAL_RC_VALIDATION` and must never be reported as PASS here.
